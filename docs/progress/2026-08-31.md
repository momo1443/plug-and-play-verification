## Session 3 (2026-09-01 early morning) — Model Collapse Discovery

### CRITICAL: A9 Uniform Training Collapsed at Step 48

**Experiment**: `qwen35-4b_a9_uniform_emwarm100_main30k_n4_1500step_6gpu_vllm025_refkl001_20260831-204316`

**What happened**: The model catastrophically forgot the XML tool-call format (`<function=search><parameter=query>...</parameter></function>`) and switched to a Python-like syntax (`search(query=...)`) at step 48. Since the tool parser only recognizes the XML format, all search calls failed, the model got no search results, and EM dropped from ~60% to 0.0000 — permanently.

**Detailed timeline**:
| Step | XML format | Python-like | Other | EM |
|------|-----------|-------------|-------|----|
| 40   | 80/80     | 0           | 0     | 85.0% |
| 41   | 79/80     | 1           | 0     | 68.8% |
| 44   | 76/80     | 3           | 1     | 61.3% |
| 47   | 76/80     | 3           | 1     | 60.0% |
| 48   | 0/80      | 77          | 3     | 0.0% |
| 50+  | 0/80      | ~80         | 0     | 0.0% |

**Training metrics at collapse boundary**:
| Metric | Step 47 | Step 48 |
|--------|---------|---------|
| score/trajectory/mean | 0.60 | 0.00 |
| response_length/trajectory | 384 | 214 |
| pg_loss | -3.2e-7 | 0.0 |
| grad_norm | 0.978 | 0.026 |
| kl_loss | 0.0067 | 0.0888 |

**Root cause analysis**:
1. **No format reward during warmup**: Steps 1-100 use `terminal_weight=1.0, process_weight=0.0`. The model only gets reward for correct final answers, NOT for correct tool-call format.
2. **Format drift before collapse**: Even at step 41, 1/80 samples already used wrong format. By step 47, 4/80 were wrong.
3. **Positive feedback death spiral**: Wrong format → tool calls fail → no search results → EM=0 → all rewards 0 → pg_loss=0 → no gradient signal → only KL penalty drives updates → model drifts further from reference → format never recovers.
4. **Self-reinforcing**: Once the model generates wrong format, it sees no examples of working search (since all its own rollouts fail), so it can't self-correct.

**Implications**: This is a fundamental design issue with the warmup schedule. During the warmup phase, the model MUST maintain correct tool-call format to get any positive reward at all, but there's no explicit reward for format compliance. The format is only implicitly rewarded via successful search → correct answer → EM=1, which is too indirect and fragile.

**Possible fixes** (need user decision):
1. **Add format compliance reward**: Even during warmup, give a small bonus for well-formed `<function=search>` calls.
2. **Format penalty**: Penalize malformed tool calls explicitly (negative reward).
3. **Reduce warmup length**: Shorter warmup means earlier introduction of process reward, which includes format signals.
4. **Use reference model KL more aggressively**: Prevent drift from the SFT model that knows the format.
5. **Rejection sampling**: Discard trajectories with malformed tool calls and re-sample.

**Current status**: Training is still running (at step 146) but completely collapsed since step 48. GPU compute is being wasted. The experiment should be stopped.
