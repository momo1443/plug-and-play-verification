## Session 2: Fix Crash and Resume A9 Training

### Crash Root Cause
Training crashed at step 14 with `TypeError: unsupported operand type(s) for +: 'int' and 'NoneType'` in `build_trajectory_dump_entries`.

Two issues:
1. `compute_score` returns dict with `"score"` key → verl's naive reward manager puts ALL dict keys into `reward_extra_info` → `build_trajectory_dump_entries` line 238-239 overwrites `step_entry["score"]` with `reward_extra_info["score"]` → padded/misaligned items have None → `sum()` crashes
2. First attempted fix: rename `"score"` to `"reward_value"` — but naive reward manager requires `"score"` key (`score = result["score"]`), causing `KeyError: 'score'`

### Final Fix (two-part)
1. **`agent_r1/trainer/ppo/ray_trainer.py` line 238-240**: Changed `for key, values in aligned_reward_infos.items(): step_entry[key] = values[idx]` to skip keys that would overwrite internal fields (`"score"`, `"step_index"`, `"input"`, `"output"`, `"gts"`)
2. **`agent_r1/trainer/ppo/ray_trainer.py` line 256**: Added `or 0` defensive fallback: `sum(step["score"] or 0 for step in steps)`
3. **`recipes/deepscaler/reward_fn.py`**: Kept `"score"` key in return dict (required by naive reward manager)
